# Interaction Patterns Domain

## Purpose
To document repeatable, complex interactive experiences decoupled from specific implementations.

## Scope
Covers the conceptual behavior of common interaction types (e.g., mega menus, page transitions).

## What Belongs Here
- State matrices for complex components
- Trigger and feedback loops
- High-level motion specifications (duration, easing)

## What Does NOT Belong Here
- The actual code to build the pattern (see Motion / JavaScript)

## Relationships
- Serves as the blueprint for **Motion** and **JavaScript** engineers.

# Knowledge Naming Conventions

To ensure the knowledge base remains searchable and scalable, all files and headings must adhere to these strict naming conventions.

## File Names
- Format: Kebab-case.
- Rule: Descriptive and concise. Do not use generic names.
- Example: `01-semantic-html.md`, `gsap-scroll-trigger-basics.md`, `mobile-navigation-pattern.md`.
- Numbering: Prefix with numbers (e.g., `01-`, `02-`) ONLY for sequential or highly foundational rules within a domain. Otherwise, use descriptive names.

## Headings
- Use sentence case for headings (e.g., "Common mistakes" instead of "Common Mistakes", except for proper nouns).
- Keep headings concise.

## Cross-References and Internal Linking
- Always use relative paths when linking to other knowledge documents.
- Use exact file names for link text when appropriate, or highly contextual text.
- Example: `[Semantic HTML](../html/01-semantic-html.md)`.

## Version Notation
- Use semantic versioning at the bottom of the document under `Version History`.
- Example: `v1.0`, `v1.1` (for minor updates), `v2.0` (for complete rewrites).

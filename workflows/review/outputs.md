# Review Outputs
## Purpose
This document specifies the expected deliverables upon completing the review phase. It defines the state of the codebase once the review is successful.

## Principles
- **Clear Resolution**: Ensure all discussions and required changes are finalized.
- **Quality Assurance**: Confirm the codebase remains stable and maintainable.

## Engineering Rules
- **Rule 1**: Produce an Approved Pull Request with all blocking comments resolved.
- **Rule 2**: Produce merged code in the target branch (e.g., main or staging).
- **Rule 3**: Produce updated issue tracker status (e.g., moving ticket to "Done" or "QA").
- **Rule 4**: Produce a triggered deployment or build process (if automated).

## Best Practices
- Ensure the author is the one who merges the PR after approval, establishing ownership.
- Document any technical debt or follow-up tasks discovered during review in new tickets.
- Celebrate significant merges or complex feature completions.

## Common Mistakes
- ❌ Merging the PR while discussions or comments are still open.
- ❌ Forgetting to update the ticket status, leading to project management confusion.
- ❌ Failing to create follow-up tickets for agreed-upon technical debt.
- ❌ Approving the code but failing to verify the deployment pipeline succeeded.

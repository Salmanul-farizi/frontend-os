# Design Analysis Outputs
## Purpose
This document specifies the expected deliverables upon completing the design analysis workflow. It sets the standard for what must be produced to move forward.

## Principles
- **Clear Deliverables**: Ensure all findings are documented and shareable.
- **Actionable Insights**: Highlight what needs immediate attention.

## Engineering Rules
- **Rule 1**: Produce a completed Design Analysis Report.
- **Rule 2**: Produce a comprehensive Component Inventory.
- **Rule 3**: Produce a Global Design Tokens specification (colors, typography, spacing).
- **Rule 4**: Produce a list of Questions for Designer regarding missing states or assets.

## Best Practices
- Store outputs in the project's central documentation repository.
- Share the Questions for Designer list as early as possible.
- Use the Component Inventory to start planning the implementation architecture.

## Common Mistakes
- ❌ Failing to formally document the outputs.
- ❌ Keeping the token specification in a local file instead of a shared space.
- ❌ Delaying the questions list until implementation begins.
- ❌ Creating incomplete component inventories.

# Design Analysis Report Template
## Purpose
This document provides the standard structure for presenting design analysis findings. It ensures that the engineering brief includes a clear, consistent summary of the design review.

## Principles
- **Clarity**: Present findings in an easy-to-understand format.
- **Actionability**: Clearly separate informational findings from required actions (e.g., questions for designers).
- **Comprehensive Coverage**: Address all key areas of the design.

## Engineering Rules
- **Rule 1**: The report must include a summary of global tokens.
- **Rule 2**: The report must list all identified components.
- **Rule 3**: The report must highlight any technical feasibility concerns.
- **Rule 4**: The report must include a list of missing assets or missing states.
- **Rule 5**: The report must enumerate specific questions for the design team.
- **Rule 6**: All complex interactions must have a dedicated section detailing expected behavior.

## Best Practices
- Use clear headings and bullet points.
- Include screenshots or links to specific frames in the design tool.
- Keep the tone objective and focused on engineering requirements.

## Common Mistakes
- ❌ Making the report too vague (e.g., "several components found").
- ❌ Failing to clearly highlight blockers or missing information.
- ❌ Overloading the report with unnecessary technical jargon.
- ❌ Forgetting to include the list of questions for the designer.
